Task 7: Model Loading, Full and Streaming.  (most likley to break thing, need to ensure data is managed correctly)
Currenly we operate in a "Full" mode loading all layers on initialization.
What we need to do for larger models that cannot fit into limited memory is have a streaming option.
This will change how InitializeWeights works,  We will need to Have InitializeLayer and InitializeWeights  should call that for sepcific layers.
This means IModelLoader that currently only has LoadAllWeights will also need a LoadLayerWeights.
This should be the only change i can initally see needed for TransformerWeights and the TransformerWeightsFull. 
From there depending on the method we are using Full or Streaming we would create a TransformerWeightsFull or TransformerWeightsStreaming.
TransformerWeightsStreaming on initilaization need to get MetaData or read data to get QuantDTypes offsets and lenght for loading into or preparing Tensors with know quant size, We do not want the permenantly taking up memeory.
Care on data flow an loading will need to be considered and attions to IModelLoader such as GetMetaDataa may be required.
Initial Layers Actualy Loaded would be the first and second may need multiple sets loaded. Then when a pass though the network is done, after the first layer is used the second should be loaded so we can asynconosly free the first and load the 3 as second is next.
This process follows through cyclically so when at the second to last layer the last layer aleardy exists and the first is being loaded.
It is crucial we are not reconstuctucting things and only allocating freeing data as required so some tracking mecanisims will need to be implemented in a manor that does not hinder current "Full" performance.
Agents, unlike instances that use "Full" if we are in "Streaming" we cannot use the same weights as the reuired layers may become out of sync so each agent spawned in an non "Full" invorement will need thier own TransformerWeightsStreaming instance.
