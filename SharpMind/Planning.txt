LLM weight merging
Weighted Averaging/Linear Merge: Takes a weighted average of the parameters from multiple models
SLERP (Spherical Linear Interpolation): Better than linear interpolation for high-dimensional spaces, as it preserves the magnitude of weights, reducing the loss of performance often seen in simple averagin
TIES-Merging (TrIm, Elect, Sign, and Merge): Designed to handle interference between models by only merging the most significant weight updates and resolving sign disagreements
DARE (Drop And REscale): Drops redundant weights and re-scales the remaining weights to create a "soups" of models, reducing task interference.
Task Arithmetic: Creates "task vectors" by subtracting the base model weights from the fine-tuned model weights, allowing these vectors to be added or subtracted to modify model behavior.

#	Fix	File	Impact

7	Remove unused FloatDescComparer class	TensorOps.cs:511-514	Cosmetic
Tier 2: 1–4 hour changes, significant speedup
#	Fix	Impact
1	Eliminate per-head Q packing / O scattering in AttentionLayer.Forward — currently copies [seqLen × headDim] per head into contiguous buffers, then scatters output back. Use strided pointer arithmetic into the batched Q/K/V tensors directly	HIGH — O(numH·seqLen·headDim) redundant moves per layer per token, ~30-50% of attention time
2	Fuse WGate + WUp into a single LinearLayer (2× output dim) in GatedFfnLayer — halves matmul launches for the gate/up projections	HIGH — ~33% fewer matmul calls per FFN layer
3	Replace top-k O(n log n) sort with O(n) quickselect in Sampler	MEDIUM — at vocab=128K, sorting dominates sampling time
4	Bulk KV cache copy with Unsafe.CopyBlock instead of element-by-element loop	MEDIUM — O(heads·seqLen·headDim) per update; CopyBlock is ~10x faster than per-element
5	Use online softmax in standard attention kernels (like flash variant) to reduce 3-pass to 2-pass and avoid the per-call ArrayPool.Rent	MEDIUM — standard kernels are still the default path for many users
6	Fix BinaryOp/UnaryOp delegate indirection — Func<Vector<T>, Vector<T>> is a virtual call that JIT can't inline. Use INumber<T> generic math with static abstract interface methods (SAIM, .NET 9) or explicit per-type overloads	MEDIUM — affects every elementwise op (Add, Scale, etc.)
7	Avoid Tensor.this[params int[]] on hot paths — params always allocates an array	LOW — only if users call multi-index accessors in tight loops
Tier 3: Architectural changes (days), biggest overall wins
#	Fix	Impact
1	Incremental prompt encoding in ChatSession — cache _lastEncodedTokens and append new user message + assistant prefix only, instead of re-encoding the full history each turn	HIGH — eliminates O(N²) encoding cost over long conversations
2	Proper speculative decoding — currently draftCount=1, zero speedup. Needs a draft model (or self-speculation) + rejection sampling + KV-cache rollback	HIGH — can give 1.5-2.5× latency improvement
3	Fused end-to-end attention kernel — eliminate per-head packing, RoPE → cache → attention in a single pass from the strided Q/K/V layout	HIGH — the single biggest inference bottleneck
4	Pre-allocate KV cache to maxSeqLen to avoid O(log N) growth cost and GC spikes	MEDIUM — simplifies code, eliminates resize stalls
5	NativeBufferPool lock contention — use ConcurrentStack directly with Interlocked for counters instead of lock	MEDIUM — matters under high-throughput training
6	Switch Parallel.For to sequential for small head counts (e.g., <16) — Parallel.For overhead can dominate when iterations are few	MEDIUM — improves single-batch decode latency
